# 台股妖股篩選系統

用證交所、櫃買中心的公開資料，每天找出具有「妖股」特徵的上市櫃股票。
只用 Python 3 內建函式庫，不需要安裝套件，也不需要 API 金鑰。

## 網頁版（妖股雷達）

在 Finder 雙擊 `啟動妖股雷達.command`，或在終端機執行：

```bash
cd ~/tw-yaogu-screener
python3 server.py
```

瀏覽器會自動開啟 http://localhost:8765 。網頁可以：

- 調整最低分數、成交張數、小股本門檻，篩選上市／上櫃；點「ⓘ 評分依據」可看計分規則、各門檻的意義與今天各門檻的檔數
- 只看漲停、排除處置股、搜尋代號或名稱
- 點欄位標題排序；點股票查看得分明細（每一項加幾分）與近 60 日 K 線（含 5 日均線、前 60 日高點）
- 用鍵盤 ↑ ↓ 切換股票
- **連續上榜天數**：妖股雷達依目前設定的最低分數，往回計算每檔連續達標的天數（最多 20 天，可排序）；
  明日強勢候選、起漲前夕顯示連續符合條件的天數（明日候選也套用法人賣超排除），LINE 卡片同步顯示

### 即時行情

今天的官方收盤資料還沒公布時（盤中，或收盤後到約 15:00 之間），會改用證交所「基本市況報導」的即時行情（延遲約 5～20 秒）掃描全市場，約需 30～40 秒：

- 盤中每 3 分鐘自動更新全市場，標示「盤中即時」
- 點開的個股每 10 秒更新一次即時報價
- 13:35 之後的快照視為今日收盤；官方資料公布後自動改用官方資料

即時行情不含盤後定價交易，成交量會比官方資料略少；冷門股收盤後若沒有最新成交價，會以委買價估計。

### 隔日沖（網址 `#overnight`）

每個交易日 13:00 用盤中即時行情選股（收盤前約 25 分鐘可以下單），LINE 推播「⚡ 隔日沖候選」：盤中漲到 +7% 以上（開盤時還沒到 +7%）、
股價接近或突破 60 日高點、成交量 1,000 張以上，排除處置股，越接近漲停排越前面，最多 10 檔。
**收盤前買進、明天開盤一律賣出。**

- 11 年研究（`research/overnight.py`）：「漲到 +7% 就買、接近或突破 60 日高、隔天開盤賣」
  訓練期勝率 49.9%、平均 +0.17%，驗證期勝率 50.7%、平均 +0.26%（已扣成本）；隨便一檔約勝率 35%、平均 -0.2%
- 收盤鎖住漲停的股票隔天開盤平均 +1.6～2.0%、勝率約 70%，但收盤前通常買不到；漲停被打開的隔天開盤平均 -0.9%
- 抱到隔天收盤的結果明顯較差；只有每日開高低收資料，無法驗證中午 12 點時的狀態

### 明日強勢候選（網址 `#picks`）

收盤後找出「放量突破 60 日高點、收在最高價附近、均線向上，但 5 日漲幅還不到 20%」的股票，
並**排除當天三大法人賣超**的股票（三大法人資料約 15:00 後公布，公布前不排除），每檔列出：

- **為什麼列入候選**：符合的條件與實際數字
- **價位**：進場區間（突破點或收盤 -3% ～ 收盤 +3%）、停損（今日最低，或收盤 -7%）、
  目標一（風險的 1.5 倍，先賣一半並把停損移到成本）、目標二（風險的 3 倍，全部出場），最多持有 3 天
- **風險**：爆量、上影線、注意股、一字漲停買不到等

頁面最上方會顯示這套規則用近 2 年（約 520 個交易日）、完全照上述價位進出的回測結果（含交易成本，已排除法人賣超）。
**2 年研究顯示這套規則跟隨便買幾乎沒有差別，請當作觀察名單，不是保證獲利的買進訊號。**
規則寫在 `strategy.py`，可以自行調整條件後看回測數字的變化。

### 起漲前夕（網址 `#pre`）

找出「近 20 日箱型整理（高低差 ≤ 15%）、成交量萎縮（20 日均量 ≤ 60 日均量）、5／10／20 日均線糾結（差距 ≤ 3%），
股價貼近箱頂，今天溫和放量收紅」但**還沒突破**的股票，只列型態完整度最高的前 10 檔（回測也是每天只做前 10 檔）。**大盤（加權指數）跌破 20 日均線時，整頁標示暫停。**每檔列出突破買進價（箱頂上一檔）、停損（箱底，或突破價 -7%）、
目標（箱頂 + 箱型高度），K 線圖上會畫出箱頂與箱底。

頁面上會顯示回測結果（大盤多頭才做、漲過箱頂才進場、5 天內沒突破放棄、最多持有 10 天），
並和「大盤多頭日任意股票隔日買、抱 10 天」比較。**2 年研究顯示型態本身跟隨便買差不多，請當作觀察名單。**

使用期間請保持終端機視窗開著，關掉視窗或按 Ctrl+C 就會停止。

### 營收動能（網址 `#rev`）

每月 11 日營收公布後的第一個交易日收盤選股（`revenue.py`）：**營收創近 12 個月新高、營收年增 > 20%、股價站上季線**，
日均量 500 張以上，依 20 日成交值取前 20 檔。隔天開盤平均買進、持有 20 個交易日，到下次換股日再換。

- 11 年研究（`research/revenue_long.py`，2015/04～2026/08，137 次選股）：90 個月贏過所有股票，平均每月多 2.4 個百分點，
  每一年都贏，包括 2018、2022 空頭年；個股勝率 51.3%（所有股票 46.8%），最差一個月 -18.8%
- 頁面顯示本期名單、入選理由、換股後報酬與最近 2 年逐月回測；換股日當天 LINE 推播本月名單
- 月營收來源：公開資訊觀測站月營收彙總表；每月 11 日起才使用上個月營收，避免偷看未來

### 0050 專區（網址 `#etf`）

每天告訴你 0050 怎麼買，依據是 2012 年至今約 13 年的回測（`etf.py`，`research/etf_study.py`）：

- **建議**：每月固定買、越早越好，本月還沒買的話「明天開盤直接買」。回測中所有「掛低價等回檔」的買法，
  平均成本都比每月第一個交易日開盤直接買高 0.3%～1.2%，三個子期間結果一致
- **參考價位**：月線、季線、半年線，附上歷史上 20 個交易日內碰到該價位的機率
- **溫度計**：目前比季線高多少、在 13 年中的百分位（偏冷／正常／偏熱）；回測顯示偏熱時暫停或減碼並不會比較好
- **回測表**：各種買法相對定期定額的平均成本差異，每天自動更新

價格使用還原股價（含配息與 2025/06 的一拆四），資料來源為證交所 STOCK_DAY，每月一次請求並快取。

### 2 年研究（`research/`）

`research/download_history.py`、`research/download_extra.py` 下載 2 年股價、加權指數與三大法人資料，
`research/study.py` 把兩套策略加上各種條件後回測：前 75% 期間用來找條件、最後 25% 只用來驗證，
並與同期間任意股票比較，避免把巧合當成規律。結論（2024/08～2026/10）：

- 兩套策略本身都跟隨便買幾乎沒有差別，沒有任何條件能讓訓練期轉為正報酬
- 在兩段期間都成立的只有兩點，已套用：明日強勢候選排除法人賣超；起漲前夕在大盤跌破 20 日均線時暫停

## 網路版（GitHub Pages）

`.github/workflows/update.yml` 會在每個交易日台灣時間 15:40、16:20、17:10、18:30、20:15 自動執行（GitHub 排程可能延遲或被略過，所以安排多次；LINE 同一天只發送一次）：

1. 下載當天行情（前一次的資料存在 GitHub Actions 快取，不用重抓；快取不足 2 年時，先從 Release `data-seed` 下載初始資料）
2. 執行 `export_site.py`，把篩選結果、明日候選、回測與 K 線資料存成 `site/data/*.json`
3. 發佈到 GitHub Pages

GitHub 排程常延遲或被略過，所以有三道觸發，LINE 同一交易日只發送一次、重複執行也不會重複推播：

1. **cron-job.org**（主要）：平日 15:50、16:50 以 POST 呼叫 GitHub API
   `https://api.github.com/repos/ghiting76914-sys/tw-yaogu-screener/actions/workflows/update.yml/dispatches`，
   標頭 `Authorization: Bearer <GitHub 金鑰>`、body `{"ref":"main"}`。金鑰為只限本專案、Actions 讀寫權限的
   fine-grained token（`cron-job-yaogu`），**一年後到期需要重新產生並更新到 cron-job.org**
2. **GitHub 自己的排程**（`update.yml` 的 schedule）
3. **這台 Mac**（最後保險）：launchd（`~/Library/LaunchAgents/com.ghiting.yaogu-trigger.plist`）在平日 16:10、17:00
   執行 `scripts/trigger_update.sh`，網站上的交易日還不是今天就觸發一次，紀錄在 `output/trigger.log`。
   Mac 睡眠時會在醒來後補跑。停用：`launchctl unload ~/Library/LaunchAgents/com.ghiting.yaogu-trigger.plist`

**13:00 盤中預覽（隔日沖）**：cron-job.org 另一個工作在平日 13:00 以同樣方式呼叫 GitHub API，
body 為 `{"ref":"main","inputs":{"preview":"true"}}`（GitHub 排程也有 13:00 的備援，Mac 在 13:05 檢查）。
`export_site.py --preview` 改用證交所即時行情當作今天，成交量依已過的交易時間換算成全天預估，
網站標示「盤中預覽」，LINE 推播「⚡ 隔日沖候選」（收盤後才推播明日強勢候選）。三大法人資料尚未公布、不排除法人賣超；
名單會隨收盤變動，回測只適用收盤後的正式名單。盤中預覽與正式名單的 LINE 推播分開記錄、各一天一次。

網路版是靜態網頁，沒有盤中即時報價，也不能自訂成交量、股本門檻（固定為 500 張、10 億）。
想立即更新，可以到 GitHub 專案的 Actions 頁面，對「每日更新妖股雷達」按 Run workflow。

本機預覽靜態版：`python3 export_site.py && cd site && python3 -m http.server`

## LINE 通知

每天更新完成後，`notify_line.py` 會把明日強勢候選以可左右滑動的卡片推播到 LINE（營收動能換股日另外附上本月名單）：
每檔一張卡片（價格、進場區間、停損、目標一／目標二、入選理由、風險、看 K 線按鈕），最後一張是回測成績。
整組卡片只算 1 則訊息額度；若卡片格式被 LINE 拒絕，會自動改傳純文字版。
同一個交易日只發送一次。使用 LINE 官方帳號 Messaging API（LINE Notify 已於 2025 年停止服務）。

**預設群發給所有加「妖股雷達」官方帳號為好友的人。** 免費方案每月 200 則，群發依人數計算：
每天 1 次推播、一個月約 22 次，所以免費方案大約可以給 9 個人；超過額度當月剩下的推播會失敗。
每次發送後，執行紀錄會顯示本月已用額度。若只想傳給自己，到 GitHub 專案的
Settings → Secrets and variables → Actions → Variables 新增 `LINE_SEND_TO`，值填 `me`。

設定方式：

1. 到 [LINE Developers](https://developers.line.biz/console/) 用 LINE 帳號登入，建立 Provider，再建立 **Messaging API** channel（會同時建立一個 LINE 官方帳號）
2. 在 channel 的 **Messaging API** 分頁最下方，發行 **Channel access token (long-lived)**
3. 在 **Basic settings** 分頁最下方，複製 **Your user ID**（U 開頭）
4. 用手機 LINE 掃 **Messaging API** 分頁的 QR code，把官方帳號加為好友
5. 把兩組值存成 GitHub Secrets：

```bash
gh secret set LINE_CHANNEL_ACCESS_TOKEN --repo ghiting76914-sys/tw-yaogu-screener
gh secret set LINE_USER_ID --repo ghiting76914-sys/tw-yaogu-screener
```

預覽訊息內容：`python3 notify_line.py --dry-run`

## 命令列版

```bash
python3 yaogu.py                    # 最近交易日（建議 15:00 收盤資料公布後執行）
python3 yaogu.py --date 20260930    # 指定日期
python3 yaogu.py --min-score 8      # 只看高分
python3 yaogu.py --small-cap 5      # 小股本門檻改為 5 億
```

第一次執行會下載約 520 個交易日（2 年）的行情，需要幾分鐘（證交所限制請求頻率）。
之後會讀取 `data/cache/` 裡的快取，每天只需要補抓當天的資料。
結果會印在終端機上，完整清單另存成 `output/yaogu_YYYYMMDD.csv`，可以直接用 Excel 開啟。

## 評分規則

| 條件 | 分數 |
|---|---|
| 股本 < 10 億 / < 20 億 | +2 / +1 |
| 量比（當日量 ÷ 前 20 日均量）≥ 3 / ≥ 2 | +2 / +1 |
| 漲停（漲幅 ≥ 9.5%），連續漲停每多一天再 +1（最多 +3） | +2 起 |
| 未漲停但漲幅 ≥ 5% | +1 |
| 5 日漲幅 ≥ 20% / ≥ 10% | +2 / +1 |
| 收盤突破前 60 日最高價 | +2 |
| 週轉率 ≥ 10% | +1 |
| 列入注意股 | +1 |
| 處置股 | 只標示，不加分 |

預設只列出分數 ≥ 6、成交量 ≥ 500 張的一般股票（排除 ETF、權證）。
評分邏輯集中在 `yaogu.py` 的 `analyze()`，可以依自己的需求調整。

## 參數

| 參數 | 預設 | 說明 |
|---|---|---|
| `--date` | 今天 | 篩選日期 YYYYMMDD |
| `--min-score` | 6 | 最低分數 |
| `--top` | 50 | 終端機最多顯示幾檔 |
| `--min-volume` | 500 | 最低成交張數 |
| `--small-cap` | 10 | 小股本門檻（億元） |
| `--lookback` | 61 | 抓取的交易日數 |

## 每天自動執行（選用）

用 crontab 在平日 15:30 執行：

```
30 15 * * 1-5 cd ~/tw-yaogu-screener && /usr/bin/python3 yaogu.py >> output/cron.log 2>&1
```
